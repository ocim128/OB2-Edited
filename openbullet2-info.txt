# OpenBullet2 Native - Comprehensive Technical Documentation

## Overview
OpenBullet2 Native is a WPF-based desktop application for automation testing, data scraping, and proxy checking. It provides a comprehensive interface for managing configurations, jobs, wordlists, proxies, and monitoring execution results. The application uses MVVM architecture with dependency injection and real-time updates.

## Application Architecture

### Core Structure
- **Framework**: WPF (.NET 8) with Metro UI styling (MahApps.Metro)
- **Architecture**: MVVM (Model-View-ViewModel) with dependency injection
- **Database**: SQLite with Entity Framework Core
- **File System**: User data stored in `UserData/` directory
- **Configuration**: appsettings.json for application settings

### Service Layer (Dependency Injection)
```
├── Core Services
│   ├── ConfigService - Manages automation configs
│   ├── JobManagerService - Controls job execution
│   ├── JobMonitorService - Real-time job monitoring
│   ├── HitStorageService - Manages captured results
│   └── ProxyReloadService - Handles proxy management
├── Repositories
│   ├── DbProxyRepository - Database proxy operations
│   ├── DbHitRepository - Hit storage/retrieval
│   ├── DiskConfigRepository - Config file management
│   └── HybridWordlistRepository - Wordlist storage
└── Utilities
    ├── VolatileSettingsService - Runtime settings
    ├── AnnouncementService - Update notifications
    └── UpdateService - Auto-update functionality
```

## Data Flow Architecture

### Job Execution Flow
```
1. User creates job → JobsViewModel
2. Job configuration → MultiRunJobViewerViewModel
3. Job start → JobManagerService
4. Parallelizer selection → TaskBased/Thread/ParallelBased
5. Real-time updates → Timer-based ViewModel updates
6. Results capture → HitStorageService
7. UI feedback → Observable collections, property binding
```

### Configuration Management
```
1. Config selection → ConfigsViewModel
2. Config editing → Multiple specialized ViewModels
3. File operations → DiskConfigRepository
4. Validation → RuriLib engine
5. Execution → Job system integration
```

### Data Binding Strategy
- **MVVM Pattern**: Clean separation of concerns
- **Observable Collections**: Real-time UI updates
- **Property Binding**: Two-way data binding where needed
- **Command Pattern**: Button actions and menu commands
- **Converter Usage**: Data transformation for display

## Performance Considerations

### UI Performance
- **Virtualization**: Large lists use virtualized controls
- **Throttled Updates**: Timer-based rather than event-driven updates
- **Background Operations**: Heavy work off UI thread
- **Memory Management**: Proper disposal of resources

### Parallelization Integration
The Native UI integrates with three parallelizers:

#### TaskBasedParallelizer
- **Best for**: File operations, HTTP requests
- **UI Integration**: Real-time bot monitoring
- **Critical Pattern**: `.ContinueWith()` for task completion
- **Performance**: High concurrency scenarios

#### ThreadBasedParallelizer  
- **Best for**: CPU-intensive operations
- **UI Integration**: Thread-safe status updates
- **Performance**: Lower overhead for simple operations

#### ParallelBasedParallelizer
- **Best for**: Batch processing
- **UI Integration**: Batch-based progress updates
- **Performance**: CPU-bound parallel work

### Memory Management
- **IDisposable**: Proper resource cleanup
- **Timer Disposal**: Cleanup on ViewModel disposal
- **Event Unsubscription**: Prevent memory leaks
- **Service Lifetime**: Singleton services for shared resources
